# Resilience

This section documents the architectural work to keep the Personalised Lobby service serving traffic under high or critical load. The guiding principle:

> Under load, **preserve the core user journey** — even if that means turning off everything else.

Two complementary pieces are documented here:

- A **service-tier classification** that defines which endpoints are essential to the core user journey, so non-critical paths can be shed first when the system is under pressure.
- A **global circuit breaker** (`PostCloudWatchController`) that observes pressure on the lobby stack via CloudWatch alarms, decides when to shed, and persists that decision to DynamoDB for downstream Lambdas to read.
